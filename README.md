# 稽古堂 · 公版文本注释版编辑工具

面向公版古籍整理者的章节、句子和词语级注释工作台。支持脚注、异文、背景说明与交叉引用，并可在阅读版、编辑版、校勘版之间切换，解决不同来源之间的注释冲突。

## 功能

- 按章节、句子和词语选择注释目标，维护脚注、异文、背景说明和交叉引用。
- 使用稳定 ID 保存正文与注释关系；句子修订后，失效的词级引用自动迁移到所属句，避免悬空引用。
- 章节保存为携带正文版本（基线 revision）的增量提交：两个窗口同时工作时，只改不同目标自动三方并入，不再整份覆盖。
- 同一注释（或同一句正文）两边都改时列为合并冲突；仅“主校”角色可裁定采用服务端、采用本地或合并两者，其他角色提交裁定会被拒绝。
- 正文修改后词级注释失效重算：能按当前版本重新定位原词则自动改挂，找不到则降级到所属句并标记“待确认”。
- 提交按 submissionId 幂等去重，重试不会重复产生注释；写入失败保留两边原稿，可重试，重新打开窗口可继续处理。
- 交叉引用随合并结果清理；阅读版、校勘版与导出均以合并后的文档为准。
- 自动按“引用目标 + 注释类型”汇总来源冲突，可逐条选用来源或合并正文后解决。
- 阅读版按引用展开脚注，编辑版提供正文和注释编辑，校勘版并列展示来源、异文与校记。
- 章节目录跳转、正文/注释/来源全文检索，以及下一条注释快速定位。
- 每个浏览器窗口持有独立离线草稿（可模拟两位整理者同时工作），共享模拟服务端；支持故障注入演示写入失败与重试。
- 版本快照与两版差异比较，可查看句子改动、新增注释并恢复快照。
- 导出完整 HTML 阅读版或 JSON 数据，支持浏览器打印。
- 快捷键：`J/K` 上/下一条注释，`[`/`]` 上/下句，`/` 聚焦搜索，`Alt+1/2/3` 切换视图，`Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Shift+Z` 重做，`Ctrl/⌘+S` 提交增量并合并。
- 响应式布局：桌面使用三栏工作区，窄屏自动堆叠；所有主要按钮和编辑目标均有语义标签。

## 技术栈

- Next.js 15（App Router、静态导出）
- React 19
- TypeScript
- HeroUI + Tailwind CSS
- localStorage 离线持久化
- 浏览器内模拟接口，无后端依赖

## 本地开发

```bash
npm install
npm run dev
```

打开终端显示的本地地址。开发服务器端口由 Next.js 决定，源码未硬编码宿主端口。

## 生产构建

```bash
npm install
npm run build
```

静态产物位于 `out/`。由于启用了 `output: 'export'`，不需要 Node.js 服务即可托管。

## Docker

```bash
docker build -t sologsb-1022 .
docker run --rm -p 10022:80 sologsb-1022
```

容器内 nginx 监听 `80`，根端口表将其映射为宿主 `10022`。

## 数据说明

离线草稿、版本快照和最后编辑位置保存在当前浏览器 `localStorage`。清除站点数据会删除这些内容；导出的 HTML/JSON 可用于外部备份。

## 协同与增量提交

- 模拟服务端（`lib/sync.ts`）保存在 `localStorage`，维护文档版本号、历史版本、待裁定冲突与已处理提交号；打开两个浏览器窗口即可模拟两位整理者同时工作（每个窗口的草稿独立存放）。
- 保存 = 增量提交：客户端发送 `{ submissionId, baseRevision, role, draft }`，服务端以 baseRevision 对应的正文版本为共同祖先做三方合并。
- 正文按句、注释按 ID 判断“本地改 / 服务端改”：只有一方改动自动并入；两边都改同一目标则记录冲突，由主校在“协同”页裁定。
- 合并后统一重算词级注释锚点并清理交叉引用；客户端以合并结果刷新阅读、校勘与导出。
- 提交号幂等：重试同一提交直接返回首次结果；故障注入可演示“写入失败”（未落盘，可重试）与“写入后响应丢失”（重试走幂等去重）。
